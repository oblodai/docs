Приём криптоплатежей в биллинге WHMCS. Инструкция подходит для **WHMCS 6, 7 и 8** — различия
версий отмечены прямо в шагах. Без программирования.

**Совместимость и файлы модуля:**

| Версия WHMCS | Файл модуля | Автозагрузчик |
|---|---|---|
| **WHMCS 6.x** | `oblodai-whmcs-6.zip` | встроенная папка `include/` (composer не нужен) |
| **WHMCS 7.x** | `oblodai-whmcs-7.zip` | composer-автолоадер уже собран внутри zip |
| **WHMCS 8.x** | `oblodai-whmcs-8.zip` | composer-автолоадер уже собран внутри zip |

**Где скачать:** кабинет [my.oblodai.com](https://my.oblodai.com) → «Загрузки».

<Note>
  Скачайте **один** zip — строго под вашу версию WHMCS. Файлы разных версий не взаимозаменяемы.
  Версию WHMCS видно в админке внизу страницы или в **Help → Update WHMCS**.
</Note>

## Шаг 1. Установите файлы модуля

WHMCS **не** устанавливает платёжные шлюзы через загрузку архива в админке — файлы нужно
скопировать на сервер вручную (по FTP/SFTP или через файловый менеджер хостинга).

<Note>
  **Что такое FTP/SFTP?** Это способ загрузить файлы на сервер вашего сайта — через отдельную
  программу (например, бесплатную FileZilla) или через «Файловый менеджер» в панели вашего хостинга.
  Данные для входа (адрес сервера, логин, пароль) даёт хостинг. «Корень сайта» — это папка, где
  лежит файл `index.php` вашего WHMCS; именно относительно неё указаны пути `modules/gateways/...`
  ниже.
</Note>

1. Скачайте zip под свою версию (см. таблицу выше) и распакуйте его на компьютере.
2. Внутри увидите:
   - файл модуля `oblodaigateway.php`;
   - папку `oblodaigateway/` (в ней библиотека: `include/` для WHMCS 6, `vendor/` для WHMCS 7/8);
   - папку `callback/` с файлом `oblodaigateway.php`.
3. Подключитесь к серверу по FTP/SFTP и откройте папку установки WHMCS.
4. Скопируйте:
   - `oblodaigateway.php` и папку `oblodaigateway/` → в `modules/gateways/`;
   - файл из `callback/` → в `modules/gateways/callback/`.
5. Итоговая структура на сервере:
   ```
   modules/gateways/oblodaigateway.php
   modules/gateways/oblodaigateway/        (папка с библиотекой)
   modules/gateways/callback/oblodaigateway.php
   ```

<Note>
  Загружайте **всю** папку `oblodaigateway/` целиком — без неё модуль не запустится.
  Для WHMCS 7 и 8 composer-автолоадер уже собран внутри архива, никаких `composer install`
  и других действий выполнять не нужно.
</Note>

## Шаг 2. Активируйте шлюз и введите ключи

1. Войдите в админку WHMCS.
2. Откройте **Настройки → Платежи → Способы оплаты**
   (шестерёнка **Setup → Payments → Payment Gateways**).
3. Перейдите на вкладку **All Payment Gateways** (все доступные шлюзы).
4. Найдите в списке **Oblodai** и нажмите на него — шлюз активируется и переключит вас на вкладку
   **Manage Existing Gateways**.
5. На вкладке **Manage Existing Gateways** заполните поля:
   - **Public ID** — ваш публичный идентификатор из кабинета Oblodai.
   - **API secret** — ваш секрет из кабинета Oblodai.
   - (необязательно) остальные поля — см. таблицу «Настройки (подробно)» ниже.
6. Нажмите **Save Changes** (Сохранить изменения).

<Note>
  Ключи (Public ID и API secret) берутся в кабинете [my.oblodai.com](https://my.oblodai.com) —
  см. [Регистрация и ключи](/guides/get-keys).
</Note>

<Note>
  **Вебхук регистрируется автоматически.** У WHMCS нет отдельного события «при сохранении»,
  поэтому модуль сам зарегистрирует вебхук в Oblodai и запомнит его секрет **при первом платеже**.
  Вручную настраивать адрес уведомления или секрет не нужно.
</Note>

## Шаг 3. Проверьте

1. В админке создайте тестовый счёт: **Billing → Create Invoice**, добавьте небольшую сумму.
2. Откройте счёт от лица клиента (кнопка **View Invoice**) и выберите способ оплаты **Oblodai**.
3. Нажмите кнопку оплаты («Pay with Oblodai» / «Pay Oblodai») — вас перенаправит на страницу
   оплаты Oblodai.
4. Оплатите тестовую сумму в крипте.
5. Вернитесь в WHMCS — счёт должен автоматически смениться на статус **Paid** (оплачено), как только
   оплата подтвердится и придёт вебхук.

## Настройки (подробно)

| Поле | Версии | Что делает |
|---|---|---|
| **Public ID** | 6 · 7 · 8 | Публичный идентификатор ключа (заголовок `X-Public-Id`). |
| **API secret** | 6 · 7 · 8 | Секрет для подписи запросов и авто-регистрации вебхука. Хранится на сервере. |
| **Subtract** | 6 · 7 · 8 | Какой процент комиссии за приём (0–100%) переложить на клиента. |
| **Pay Now Button Text** | 6 · 7 · 8 | Текст кнопки оплаты на странице счёта. |
| **Invoice Lifetime** | только 8 | Сколько действует счёт (1–12 часов). |
| **Comission** | только 8 | Учитывать комиссию на стороне клиента (Да/Нет). |
| **Convert fiat to admin default currency** | только 8 | Конвертировать фиат в валюту по умолчанию (для админ-панели). |

<Note>
  В WHMCS 6 и 7 набор полей минимальный: **Public ID**, **API secret**, **Subtract** и текст кнопки.
  Дополнительные настройки (время жизни счёта, режим комиссии, конвертация валюты) есть только в
  модуле для WHMCS 8.
</Note>

## Если что-то не работает

- **Шлюза «Oblodai» нет на вкладке All Payment Gateways** → файлы скопированы не в ту папку или
  переименованы. Проверьте, что на сервере есть именно `modules/gateways/oblodaigateway.php` и
  папка `modules/gateways/oblodaigateway/` целиком (для WHMCS 7/8 внутри должна быть папка `vendor/`,
  для WHMCS 6 — `include/`).
- **После оплаты счёт не помечается Paid** → сайт WHMCS должен быть **доступен из интернета**
  (не `localhost`), иначе вебхук не дойдёт. Сделайте ещё один тестовый платёж, чтобы модуль заново
  попытался зарегистрировать вебхук.
- **Ошибка при оплате / 401** → скопируйте **Public ID** и **API secret** заново, без пробелов по
  краям, и снова нажмите **Save Changes**.
- **«Error processing payment»** на странице счёта → чаще всего неверные ключи или сумма/валюта счёта
  не поддерживаются. Проверьте ключи и загляните в **Utilities → Logs → Module Log** (там модуль
  пишет ответ Oblodai под именем `Oblodai`).
- **Для WHMCS 7/8:** composer-автолоадер уже собран внутри архива — если модуль ругается на автолоадер,
  значит папка `oblodaigateway/vendor/` не загрузилась целиком. Перезалейте её.
- Общая диагностика — [FAQ и устранение неполадок](/guides/faq-troubleshooting).
