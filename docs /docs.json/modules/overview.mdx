Готовые платёжные модули для популярных платформ. Установили, ввели ключ (public_id + secret) — приём
криптоплатежей работает. **Программировать не нужно.**

<Note>
  **Новичку:** это самый простой способ. Если у вас магазин на одной из платформ ниже — не пишите
  код и не трогайте SDK, просто установите модуль.
</Note>

## Где скачать модули

Все zip-файлы модулей лежат в вашем кабинете: [my.oblodai.com](https://my.oblodai.com) → раздел
**«Загрузки»**. Там же будет нужная версия под вашу платформу (например, `oblodai-woocommerce.zip`,
`oblodai-opencart-3.zip`, `oblodai-whmcs-8.zip`).

<Note>
  Прямые ссылки на скачивание будут добавлены сюда позже — пока берите файлы в кабинете.
</Note>

## Что понадобится (для любого модуля)

1. **Ваш API-ключ из кабинета Oblodai.** Ключ **один**, но состоит из **пары значений** — их и надо
   вставить в настройки модуля:
   - **Public ID** — несекретный идентификатор ключа (уходит в заголовке запроса).
   - **API secret** — секретная половина, которой подписываются запросы. Храните в тайне.

   Это **не два разных ключа** и не «ключ для приёма» + «ключ для выплат»: одного ключа хватает на
   всё — приём платежей, выплаты и вебхуки. Где его взять — см.
   [Регистрация и ключи](/guides/get-keys).
2. **Доступ к админке** вашей CMS/биллинга, чтобы установить модуль и вставить ключи.
3. **Сайт доступен из интернета** — чтобы Oblodai мог присылать уведомления об оплате (вебхуки).

## Как это работает (одинаково везде)

1. Скачиваете zip модуля для вашей платформы.
2. Устанавливаете его в админке (загрузка модуля/расширения).
3. Открываете настройки способа оплаты, вставляете **Public ID** и **API secret**, сохраняете.
4. **Вебхук регистрируется автоматически** при сохранении настроек — модуль сам сообщает Oblodai,
   куда слать уведомления об оплате, и сохраняет секрет для их проверки. Вручную ничего настраивать
   не нужно. **Исключение — WHMCS:** там вебхук регистрируется при первом платеже (у WHMCS нет
   события сохранения настроек).
5. Готово: покупатель на оформлении заказа выбирает «Оплатить криптовалютой», платит на hosted-странице
   Oblodai, а после оплаты заказ автоматически помечается оплаченным.

## Общие принципы

- **Секрет — только на сервере.** Модуль работает на вашем сервере; API secret никогда не показывается
  покупателю.
- **Статус заказа меняет вебхук.** Даже если покупатель закрыл вкладку после оплаты, заказ обновится,
  когда придёт уведомление от Oblodai.
- **Тест перед боем.** Сделайте заказ на небольшую **реальную** сумму (песочницы нет) и убедитесь, что после оплаты статус
  меняется автоматически.
- **Обновление ключей.** Сменили ключ в кабинете — просто вставьте новый в настройках модуля и сохраните
  (вебхук перерегистрируется автоматически).
- **Валюта магазина уходит как есть.** Модуль отправляет валюту вашего магазина в поле `currency`.
  Поддерживаются 23 фиатные валюты (USD, EUR, GBP, RUB, UAH, PLN, CZK, TRY, CNY, INR, BRL, CAD, AUD,
  CHF, AED, ZAR, MXN, IDR, THB, VND, NGN, JPY, KRW). Если валюта магазина в этот список не входит
  (например **BYN, KZT, KGS, UZS**), шлюз вернёт `payment.unknown_currency` и платёж не создастся —
  переключите магазин на поддерживаемую валюту.

<Warning>
  **Про идемпотентность.** Модули **не** шлют заголовок `Idempotency-Key` — всё, что написано о нём
  в разделе [SDK](/sdk/overview), к модулям **не относится**. Защита от дублей здесь держится на
  **`order_id`**: модуль передаёт номер заказа вашей CMS, и повторный запрос с тем же номером не
  создаст второй платёж. Отдельно ничего настраивать не нужно — просто не считайте, что модуль ведёт
  себя как SDK.
</Warning>

## Логи (где смотреть, если что-то пошло не так)

Каждый модуль пишет понятные строки с префиксом `oblodai:` — регистрацию вебхука, отправку платежа,
приём и **проверку подписи** вебхука, смену статуса заказа, ошибки API. **Секреты и подписи в логи не
попадают.** Ошибки (неверная подпись вебхука, сбой регистрации, ошибка API) пишутся всегда; подробные
строки запрос/ответ включаются галочкой **«Debug log»** в настройках модуля (по умолчанию выключена).

| Платформа | Где лежат логи | Как включить подробности |
|---|---|---|
| **WooCommerce** | WooCommerce → Статус → Логи, источник `oblodai` | галочка **Debug log** в настройках метода |
| **OpenCart** | `system/storage/logs/oblodai.log` | пункт **Debug log** в настройках модуля |
| **PrestaShop** | Расширенные параметры → Логи | переключатель **Debug log** в настройках |
| **WHMCS** | Система → Журналы → Журнал модуля (`oblodaigateway`) + Журнал действий | всегда пишет (секреты маскируются) |
| **IPS** | ACP → Support → Logs | настройка **Debug log** у способа оплаты |
| **XenForo** | серверный error log / логи XF | появляется при board **debug mode** |

## Если что-то не работает

- Проверьте, что **Public ID** и **API secret** вставлены без лишних пробелов.
- Убедитесь, что сайт **доступен из интернета** (вебхуки не дойдут до `localhost`).
- Проверьте, что модуль/способ оплаты **включён** и отображается на оформлении заказа.
- **Включите Debug log** (см. таблицу выше) и повторите оплату — в логах будет видно, где рвётся.
- Частые проблемы конкретной платформы — в её инструкции (ссылки в таблице выше).
- Общая диагностика — [Что делать, если не работает](/guides/troubleshooting) и
  [FAQ](/guides/faq-troubleshooting).
